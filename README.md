# CelestialMechanics.jl

**CelestialMechanics.jl** is a high-precision orbital dynamics and perturbation theory framework built in Julia. It provides a robust, type-stable environment for simulating trajectories of celestial bodies and spacecraft around arbitrary central bodies.

The package features a seamless symbolic-numeric interface, allowing researchers to parse analytical Hamiltonians or Lagrange Planetary Equations directly from symbolic systems (Maxima) into optimized Julia code, and integrate them numerically with state-of-the-art solvers. 

---

## Main Features

### Propagators
- **Cowell's Method** — Direct Cartesian integration with high-fidelity physical models. Supports first-order (`ODEProblem`) and second-order (`SecondOrderODEProblem`) formulations, enabling symplectic integrators (e.g. `KahanLi8`) for long-term energy conservation.
- **Hamiltonian (Delaunay)** — Integration of action-angle variables from symbolic Hamiltonian inputs. Reads equations generated by external CAS tools at runtime.
- **Lagrange Planetary Equations (LPE)** — Numerical integration of classical Keplerian elements via the Lagrange planetary equations in Gaussian form.
- **N-Body** — Direct N-body propagation with support for both adaptive (Vern9, DOP853) and symplectic (KahanLi8, McAte8) integrators.
- **CR3BP** — Circular Restricted Three-Body Problem propagator with Poincare section analysis.

### Perturbation Models
- Zonal harmonics J2 through J18
- Tesseral and sectorial harmonics (C_nm, S_nm)
- Solar Radiation Pressure (SRP) with dynamic cylindrical shadow modeling
- N-body third-body gravitational perturbations (arbitrary number of perturbing bodies)
- Atmospheric drag with the Modified Harris-Priester density model (Montenbruck & Gill, 2000), including diurnal bulge effects driven by the Sun position via SPICE ephemeris

### Gravity Field Models (GravityModels module)
The `GravityModels` module reads, denormalizes, and packages spherical harmonic gravity field models from PDS SHA-format files (e.g., HgM008, GRGM1200A, GGM50A01). Coefficients in SHA files are fully normalized (geodesy 4-pi convention) and are automatically converted to the unnormalized convention used in classical celestial mechanics (Kaula, 1966). The module dynamically generates field entries (`j2`, `c22`, `s31`, etc.) up to any requested degree, requiring no manual updates when extending to higher harmonics. Output is directly compatible with `BODIES_DATA` and `create_perturbation_model`.

### SPICE Integration
Automated ephemeris retrieval and initial condition generation via NASA's SPICE kernels, with support for arbitrary reference frames and aberration corrections.

### Coordinates and Transformations
- Keplerian elements <-> Cartesian state vectors
- Delaunay canonical variables <-> Keplerian elements
- Mean anomaly <-> true anomaly (robust Newton-Raphson solver)
- Canonical unit normalization (DU, TU, VU) for numerical stability

### Analysis Tools
- Post-processing pipeline for orbital elements from Cartesian trajectories
- Poincare section computation (periapsis map, equatorial crossing, stroboscopic)
- 3D trajectory visualization (GLMakie/CairoMakie)
- Disk-streaming CSV output for long-duration simulations with bounded RAM usage

## Installation

Install directly from GitHub:

```julia
pkg> add https://github.com/guilhermedeolivpaes/CelestialMechanics.jl
```

Once registered in the Julia General Registry, install with:

```julia
pkg> add CelestialMechanics
```

**Requirements:** Julia >= 1.10. SPICE kernels are required for ephemeris-based simulations but not for standalone propagation.

## Quick Start

The example below propagates a low Earth orbit with J2 perturbation for 24 hours
using Cowell's method. No SPICE kernels are required for this configuration.

```julia
using CelestialMechanics
using DifferentialEquations
using Unitful, UnitfulAstro
using Unitful.DefaultSymbols

# Initial orbital elements (Example 10.2 - Orbital Mechanics for Engineering Students - Fourth Edition, Curtis, H. D., 2020)
ics = [
    InitialConditions(
        a0 = 8059.0km,
        e0 = 0.17136,
        i0 = 28.0°,
        h0 = 45.0°,
        g0 = 30.0°,
        f0 = 40.0°
    )
]

# Time configuration
t_start  = 0.0u"hr"
t_end    = 24.0u"hr"
step     = 1.0u"minute"
t_vec_u  = t_start:step:t_end
tspan    = (ustrip(u"s", t_start), ustrip(u"s", t_end))
t_vector = ustrip.(u"s", t_vec_u)

# Perturbation model: Earth + J2 only (no SPICE kernels needed)
perturbation_params = create_perturbation_model(:earth,
    j_harmonics = [2]
)

# Propagator options
propagator_opts = PropagatorOptions(
    propagator                   = CowellPropagator(),
    canonical_unit_normalization = true,
    integrator                   = Vern7(),
    abstol                       = 1e-8,
    reltol                       = 1e-8,
    maxiters                     = 10_000_000,
)

# Output directory (created automatically if it does not exist)
output_dir = joinpath(pwd(), "output")

# Run simulation
results = run_simulation(
    ics                 = ics,
    perturbation_params = perturbation_params,
    tspan               = tspan,
    t_vector            = t_vector,
    propagator_options  = propagator_opts,
    output_directory    = output_dir
);
```

> **Note:** Third-body perturbations (Moon, Sun), Solar Radiation Pressure and
> atmospheric drag can be driven either by SPICE ephemerides (highest fidelity,
> requires kernels via `SpiceInformations`; kernels at
> [NAIF/JPL](https://naif.jpl.nasa.gov/naif/data.html)) **or** by a SPICE-free
> analytic ephemeris — see below — which is handy for bodies that have no SPICE
> data (many asteroids, hypothetical systems, preliminary studies).

### Third-party / SRP without SPICE (analytic ephemeris)

When SPICE kernels are unavailable, supply an `AnalyticEphemeris`: each perturbing
body (and the Sun, for SRP/drag) follows a fixed two-body Keplerian orbit about the
central body, with only the mean anomaly advancing in time. Register the bodies with
`add_body!`, keying them by the same id used as the body's `spice_id`
(e.g. `"MOON"`, `"SUN"`), then pass the ephemeris to `run_simulation`:

# Earth-centered scenario: J2 + Moon (N-body) + Sun (SRP), no SPICE kernels
perturbation_params = create_perturbation_model(:earth,
    j_harmonics    = [2],
    n_body_symbols = [:moon],
    srp_cr         = 1.5,
    srp_alpha      = 0.02u"m^2/kg",
)

eph = AnalyticEphemeris(mu_central = 398600.4418)                 # μ_earth [km^3/s^2]
add_body!(eph, "MOON"; a = 384400.0u"km", e = 0.0549, i = 5.145u"°")
add_body!(eph, "SUN";  a = 1.0u"AU", e = 0.0167, mu = 1.32712440018e11)  # μ_sun governs

results = run_simulation(
    ics                 = ics,
    perturbation_params = perturbation_params,
    tspan               = tspan,
    t_vector            = t_vector,
    propagator_options  = propagator_opts,
    analytic_ephemeris  = eph,       # SPICE-free source; omit to use SPICE instead
)

> The gravitational parameter that governs each perturber's orbit differs per body:
> a moon's geocentric orbit is governed by ≈μ_earth, while the Sun's *apparent*
> geocentric orbit is governed by ≈μ_sun. Set it per body via the `mu` keyword of
> `add_body!` (it defaults to `mu_central`).

## Roadmap

The following are currently under active development or planned for future releases:

- **Atmospheric Drag — Advanced Density Models** — Integration with `SatelliteToolboxAtmosphericModels.jl` to provide NRLMSISE-00 and Jacchia-Roberts 1971 density models as alternatives to the current Harris-Priester implementation, enabling solar-cycle-dependent density profiles for long-duration propagations.
- **Normalized Gravitational Models** — Implementation of the fully normalized associated Legendre functions and the corresponding acceleration equations, allowing direct use of normalized SHA coefficients without prior denormalization and supporting arbitrary degree and order.
- **Non-Singular Orbital Elements** — Support for equinoctial, modified equinoctial, and Poincaré canonical variables to eliminate the singularities at zero eccentricity and zero/π inclination that currently require numerical guards in the Lie series osculating corrections, enabling robust mean-to-osculating conversion across the full parameter space.

## Companion Package

`CelestialMechanics.jl` is designed to work alongside [symcelmech](https://github.com/guilhermedeolivpaes/symcelmech), a symbolical system in Maxima for analytical celestial mechanics, orbital dynamics and dynamical
systems. Together they form a hybrid symbolic-numerical ecosystem for mission design and perturbation analysis.
