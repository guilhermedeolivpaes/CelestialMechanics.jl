# CelestialMechanics.jl

**CelestialMechanics.jl** is a high-precision orbital dynamics and perturbation theory framework built in Julia. It provides a robust, type-stable environment for simulating trajectories of celestial bodies and spacecraft around arbitrary central bodies.

The package features a seamless symbolic-numeric interface, allowing researchers to parse analytical Hamiltonians or Lagrange Planetary Equations directly from symbolic systems (Maxima) into optimized Julia code, and integrate them numerically with state-of-the-art solvers. 

---

## Main Features

### Propagators
- **Cowell's Method** — Direct Cartesian integration with high-fidelity physical models. Supports first-order (`ODEProblem`) and second-order (`SecondOrderODEProblem`) formulations, enabling symplectic integrators (e.g. `KahanLi8`) for long-term energy conservation. Includes continuous root-finding callbacks (`ContinuousCallback`) for exact collision and atmospheric reentry termination.
- **Hamiltonian (Delaunay)** — Integration of action-angle variables from symbolic Hamiltonian inputs. Reads equations generated by external CAS tools at runtime.
- **Lagrange Planetary Equations (LPE)** — Numerical integration of classical Keplerian elements via the Lagrange planetary equations in Gaussian form.
- **N-Body** — Direct N-body propagation with support for both adaptive (Vern9, DOP853) and symplectic (KahanLi8, McAte8) integrators.
- **CR3BP** — Circular Restricted Three-Body Problem propagator with Poincare section analysis.

### Perturbation Models
- **Gravitational Spherical Harmonics**:
  - **Arbitrary degree and order** via Cunningham's (1970) Cartesian recurrence relations (`SphericalHarmonics` module) with preallocated workspace buffers (zero allocations in the integration loop).
  - Universal computational engine for all higher zonal ($J_n$) and tesseral/sectorial ($C_{nm}, S_{nm}$) harmonics.
  - Dedicated ultra-fast analytical path for the dominant $J_2$ perturbation (Cartesian and Hamiltonian/Lagrange formulations).
  - Full support for both **normalized** ($\bar{C}_{nm}, \bar{S}_{nm}$, geodesy $4\pi$ convention) and **unnormalized** ($C_{nm}, S_{nm}$, Kaula convention) gravity coefficients.
  - Optional Condon-Shortley phase selection (`cs_phase::Bool = false` by default, matching GMAT and standard geodesy).
- **Atmospheric Drag**:
  - Modified Harris-Priester density model (Montenbruck & Gill, 2000), including diurnal bulge effects driven by the Sun position via SPICE or analytic ephemeris.
  - Advanced empirical thermospheric density modeling with **NRLMSISE-00** via the [`SatelliteToolboxAtmosphericModels.jl`](https://github.com/JuliaSpace/SatelliteToolboxAtmosphericModels.jl) package extension (`CelestialMechanicsNRLMSISE00Ext`), supporting automatic ingestion of space weather indices ($F_{10.7}$ and $A_p$) via `SpaceIndices.jl`.
  - Configurable minimum altitude (`min_altitude`, default 100 km) for safe physical limits and continuous reentry termination.
- **Solar Radiation Pressure (SRP)** with dynamic cylindrical shadow modeling.
- **N-body Third-Body Perturbations** with arbitrary number of perturbing bodies.

### Gravity Field Models & Asteroid Polyhedral Modeling
Gravity modeling is modularized into specialized components:
- **`SphericalHarmonics`**:
  - Ingestion of official gravity models directly from NASA PDS SHA files (`.tab`/`.sha`, e.g., HgM008, GRGM1200A) and ICGEM files (`.gfc`, e.g., EGM96, EGM2008, GGM05S).
  - High-performance recursive acceleration and potential computation via `GravityHarmonics` and Cunningham's Cartesian algorithm (`cunningham_perturbation!`, `cunningham_potential`).
  - Conversion between normalized ($\bar{C}_{nm}, \bar{S}_{nm}$) and unnormalized ($C_{nm}, S_{nm}$) coefficients via `normalize_coefficients` and `denormalize_coefficients`.
- **`PolyhedralGravity`**:
  - Exact constant-density polyhedral gravity models for asteroids and irregular bodies (Werner & Scheeres, 1997).
  - Wavefront OBJ 3D shape model loader (`load_shape_obj`), simplex moments computation, and conversion of polyhedral shapes into equivalent spherical harmonic coefficients (`polyhedron_harmonics`, `polyhedron_to_body_data`).
- **`GravityModels`**:
  - Backward-compatible re-export module exposing both spherical and polyhedral capabilities.

### SPICE Integration
Automated ephemeris retrieval and initial condition generation via NASA's SPICE kernels, with support for arbitrary reference frames and aberration corrections.

### Coordinates and Transformations
- Keplerian elements <-> Cartesian state vectors
- Delaunay canonical variables <-> Keplerian elements
- Mean anomaly <-> true anomaly (robust Newton-Raphson solver)
- Canonical unit normalization (DU, TU, VU) for numerical stability

### Analysis Tools
- Post-processing pipeline for orbital elements from Cartesian trajectories
- Poincare section computation (periapsis map, equatorial crossing, stroboscopic)
- 3D trajectory visualization (GLMakie/CairoMakie)
- Disk-streaming CSV output for long-duration simulations with bounded RAM usage

## Installation

Install directly from GitHub:

```julia
pkg> add https://github.com/guilhermedeolivpaes/CelestialMechanics.jl
```

Once registered in the Julia General Registry, install with:

```julia
pkg> add CelestialMechanics
```

**Requirements:** Julia >= 1.10. SPICE kernels are required for ephemeris-based simulations but not for standalone propagation.

## Quick Start

The example below propagates a low Earth orbit with J2 perturbation for 24 hours
using Cowell's method. No SPICE kernels are required for this configuration.

```julia
using CelestialMechanics
using DifferentialEquations
using Unitful, UnitfulAstro
using Unitful.DefaultSymbols

# Initial orbital elements (Example 10.2 - Orbital Mechanics for Engineering Students - Fourth Edition, Curtis, H. D., 2020)
ics = [
    InitialConditions(
        a0 = 8059.0km,
        e0 = 0.17136,
        i0 = 28.0°,
        h0 = 45.0°,
        g0 = 30.0°,
        f0 = 40.0°
    )
]

# Time configuration
t_start  = 0.0u"hr"
t_end    = 24.0u"hr"
step     = 1.0u"minute"
t_vec_u  = t_start:step:t_end
tspan    = (ustrip(u"s", t_start), ustrip(u"s", t_end))
t_vector = ustrip.(u"s", t_vec_u)

# Perturbation model: Earth + J2 only (no SPICE kernels needed)
perturbation_params = create_perturbation_model(:earth,
    j_harmonics = [2]
)

# Propagator options
propagator_opts = PropagatorOptions(
    propagator                   = CowellPropagator(),
    canonical_unit_normalization = true,
    integrator                   = Vern7(),
    abstol                       = 1e-8,
    reltol                       = 1e-8,
    maxiters                     = 10_000_000,
    terminate_on_collision       = true,   # Terminates at surface or reentry threshold
    collision_altitude           = nothing # Defaults to min_altitude if drag active, or surface
)

# Output directory (created automatically if it does not exist)
output_dir = joinpath(pwd(), "output")

# Run simulation
results = run_simulation(
    ics                 = ics,
    perturbation_params = perturbation_params,
    tspan               = tspan,
    t_vector            = t_vector,
    propagator_options  = propagator_opts,
    output_directory    = output_dir
);
```

> **Note:** Third-body perturbations (Moon, Sun), Solar Radiation Pressure and
> atmospheric drag can be driven either by SPICE ephemerides (highest fidelity,
> requires kernels via `SpiceInformations`; kernels at
> [NAIF/JPL](https://naif.jpl.nasa.gov/naif/data.html)) **or** by a SPICE-free
> analytic ephemeris — see below — which is handy for bodies that have no SPICE
> data (many asteroids, hypothetical systems, preliminary studies).

### Third-party / SRP without SPICE (analytic ephemeris)

When SPICE kernels are unavailable, supply an `AnalyticEphemeris`: each perturbing
body (and the Sun, for SRP/drag) follows a fixed two-body Keplerian orbit about the
central body, with only the mean anomaly advancing in time. Register the bodies with
`add_body!`, keying them by the same id used as the body's `spice_id`
(e.g. `"MOON"`, `"SUN"`), then pass the ephemeris to `run_simulation`:

```julia
# Earth-centered scenario: J2 + Moon (N-body) + Sun (SRP), no SPICE kernels
perturbation_params = create_perturbation_model(:earth,
    j_harmonics    = [2],
    n_body_symbols = [:moon],
    srp_cr         = 1.5,
    srp_alpha      = 0.02u"m^2/kg",
)

eph = AnalyticEphemeris(mu_central = 398600.4418)                 # μ_earth [km^3/s^2]
add_body!(eph, "MOON"; a = 384400.0u"km", e = 0.0549, i = 5.145u"°")
add_body!(eph, "SUN";  a = 1.0u"AU", e = 0.0167, mu = 1.32712440018e11)  # μ_sun governs

results = run_simulation(
    ics                 = ics,
    perturbation_params = perturbation_params,
    tspan               = tspan,
    t_vector            = t_vector,
    propagator_options  = propagator_opts,
    analytic_ephemeris  = eph,       # SPICE-free source; omit to use SPICE instead
)
```

> The gravitational parameter that governs each perturber's orbit differs per body:
> a moon's geocentric orbit is governed by ≈μ_earth, while the Sun's *apparent*
> geocentric orbit is governed by ≈μ_sun. Set it per body via the `mu` keyword of
> `add_body!` (it defaults to `mu_central`).

### High-Degree Gravity Fields via Cunningham Recursion

For gravity expansions beyond low-order analytical formulas, evaluate arbitrary degree and order fields with zero allocations using Cunningham's Cartesian algorithm:

```julia
# 1. Automatic loading from BODIES_DATA up to degree and order 10:
perturbation_params = create_perturbation_model(:earth,
    max_degree     = 10,
    max_order      = 10,
    use_cunningham = true
)

# 2. Or direct ingestion from official ICGEM (.gfc) or NASA PDS SHA (.sha / .tab) files:
grav = load_gravity_icgem("EGM2008.gfc"; max_degree = 70)
gh   = GravityHarmonics(grav; max_degree = 70, max_order = 70)

perturbation_params = create_perturbation_model(:earth,
    gravity_harmonics = gh
)
```

### Advanced Atmospheric Drag with NRLMSISE-00

Atmospheric drag can be modeled with the native Modified Harris-Priester model or with the empirical **NRLMSISE-00** thermospheric model via the [`SatelliteToolboxAtmosphericModels.jl`](https://github.com/JuliaSpace/SatelliteToolboxAtmosphericModels.jl) extension:

```julia
using SatelliteToolboxAtmosphericModels
using SpaceIndices # for automated daily space weather indices (F10.7, Ap)

# Initialize NOAA space weather indices
SpaceIndices.init()

# Create NRLMSISE-00 atmosphere model for the reference epoch with a 100 km reentry threshold
atm = NRLMSISE00Atmosphere(
    epoch        = DateTime("2024-01-01T00:00:00"),
    min_altitude = 100.0u"km" # Safe threshold avoiding numerical density divergence
)

perturbation_params = create_perturbation_model(:earth,
    drag_cd    = 2.2,
    drag_am    = (0.5u"m^2" / 100.0u"kg"), # Area-to-mass ratio
    atmosphere = atm
)
```

### Continuous Collision and Reentry Detection

For orbital decay and atmospheric descent trajectories, Cowell's propagator integrates continuous root-finding event monitors (`ContinuousCallback`) within `DifferentialEquations.jl`. The callback tracks distance to the central body at every internal sub-step, interrupting the integration exactly when the vehicle hits the collision or reentry threshold:

```julia
propagator_opts = PropagatorOptions(
    propagator             = CowellPropagator(),
    integrator             = Vern9(),
    abstol                 = 1e-10,
    reltol                 = 1e-10,
    terminate_on_collision = true,    # default: true
    collision_altitude     = nothing  # nothing: automatically adopts atm.min_altitude if drag is active,
                                      # or the central body surface radius (0 km altitude) otherwise.
                                      # Can also take explicit values, e.g. 120.0u"km" or 0.0u"km".
)
```

### Asteroid & Irregular Body Gravity via `PolyhedralGravity`

For asteroids and small irregular bodies with 3D shape models, the `PolyhedralGravity` module computes exact constant-density gravitational fields (Werner & Scheeres, 1997) or derives spherical harmonic coefficients directly from Wavefront OBJ meshes:

```julia
using CelestialMechanics

# Load asteroid triangular mesh from an OBJ file
vertices, faces = load_shape_obj("itokawa.obj")

# Derive unnormalized spherical harmonics C_nm, S_nm up to degree 4 (reference radius R = 0.25 km)
C, S = polyhedron_harmonics(vertices, faces, 0.25; n_max = 4)

# Create a BodyData representation ready for Cowell propagation
asteroid_body = polyhedron_to_body_data(vertices, faces, 0.25; 
    name    = :itokawa, 
    density = 1900.0 # kg/m^3
)
```

## Roadmap

The following are currently under active development or planned for future releases:

- [x] **Atmospheric Drag — Advanced Density Models** — Integration with [`SatelliteToolboxAtmosphericModels.jl`](https://github.com/JuliaSpace/SatelliteToolboxAtmosphericModels.jl) providing NRLMSISE-00 density modeling with automated NOAA space weather indices via `SpaceIndices.jl`.
- [x] **Universal Cunningham Spherical Harmonics** — Full Cunningham (1970) Cartesian recurrence relations in `SphericalHarmonics` supporting both normalized (geodesy $4\pi$) and unnormalized (Kaula) gravity fields for arbitrary degree and order with preallocated workspace buffers (zero allocations in the integration loop).
- [x] **Asteroid & Small Body Polyhedral Gravity** — Dedicated `PolyhedralGravity` module with OBJ mesh ingestion, simplex moments (Werner & Scheeres 1997), and solid harmonic conversions.
- [x] **Continuous Reentry / Collision Callbacks** — Continuous root-finding event monitors for exact sub-step trajectory termination at surface or critical atmospheric reentry altitude.
- [ ] **Atmospheric Drag — Jacchia-Roberts 1971** — Planned support for the Jacchia-Roberts model as an additional thermospheric backend.
- [ ] **Dedicated Earth Perturbations Module** — Consolidation of Earth-exclusive models (geopotential ocean/solid tides, albedo/radiation pressure, high-order thermosphere) into a specialized `EarthPerturbations` extension.
- [ ] **Non-Singular Orbital Elements** — Support for equinoctial, modified equinoctial, and Poincaré canonical variables to eliminate the singularities at zero eccentricity and zero/$\pi$ inclination that currently require numerical guards in the Lie series osculating corrections, enabling robust mean-to-osculating conversion across the full parameter space.

## Companion Package

`CelestialMechanics.jl` is designed to work alongside [symcelmech](https://github.com/guilhermedeolivpaes/symcelmech), a symbolical system in Maxima for analytical celestial mechanics, orbital dynamics and dynamical
systems. Together they form a hybrid symbolic-numerical ecosystem for mission design and perturbation analysis.
